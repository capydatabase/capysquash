# E2E Architectural Solutions

**Date**: 2025-11-06
**Session**: Deep architectural analysis of E2E bugs
**Approach**: AST-first, robust dependency tracking, schema-aware processing

---

## Overview

This document provides comprehensive architectural solutions for the three bugs discovered during E2E testing of pgsquash-engine. Each bug is analyzed at the architectural level, with AST-based solutions designed to prevent recurrence.

**Bug Summary:**
- **BUG #1**: Supabase Storage Schema Not Created (HIGH severity, P0)
- **BUG #2**: Function Schema Differences After Squashing (HIGH severity, P0)
- **BUG #3**: Index on Non-Existent Column (MEDIUM severity, P1)

**Design Principles:**
1. **AST-First**: All solutions use AST processing, not regex
2. **Tracker as Source of Truth**: Leverage unified tracker for state management
3. **Dependency-Driven**: Proper dependency tracking prevents ordering issues
4. **Schema-Aware**: Track schemas as first-class objects with dependencies

## BUG #1: Supabase Storage Schema Not Created

### Severity & Impact
- **Severity**: HIGH
- **Priority**: P0
- **Impact**: Complete migration failure on fresh database
- **Frequency**: Common (affects all Supabase projects with storage)

### Root Cause Analysis

#### The Problem
The Supabase plugin detects storage-related patterns (`storage.objects`, `storage.buckets`) and creates RLS policies for them, but **fails to ensure the `storage` schema exists first**. This results in:

```sql
-- Generated by pgsquash (missing schema creation):
CREATE POLICY avatar_upload_own ON storage.objects FOR INSERT ...
-- ERROR: pq: schema "storage" does not exist
```

#### Architectural Analysis

**Where the bug originates:**

1. **Detection Phase** (`internal/plugins/supabase/supabase.go:70-79`):
   - Plugin correctly detects `storage.objects` and `storage.buckets` patterns
   - Sets `stmt.Category = types.CategoryCritical` for storage policies
   - BUT: Does not inject schema creation dependency

2. **Compatibility Layer** (`internal/plugins/auth/compatibility.go:242-276`):
   - `GenerateSupabaseCompatibility()` creates `storage` schema and tables
   - This compatibility SQL is ONLY used for validation containers
   - NOT injected into squashed migration output

3. **Dependency Tracking** (`internal/tracking/unified_tracker.go`):
   - Tracker does NOT track schema-level dependencies
   - When parsing `CREATE POLICY ... ON storage.objects`, it extracts:
     - Table dependency: `storage.objects`
     - BUT NOT: Schema dependency: `storage`
   - Schema tracking gap: Schemas are not ObjectLifecycle entries

4. **Builder Phase** (`internal/builder/sql.go`):
   - Builder organizes by category (Extensions → Foundation → Security)
   - Assumes schemas are created by migrations explicitly
   - No implicit schema creation for cross-schema references

**Why it worked in validation but failed in real application:**

```
Validation Container:
  1. Apply compatibility layer (creates storage schema)
  2. Apply squashed migrations (policies work because schema exists)

Real Database:
  1. Apply squashed migrations (policies fail - no storage schema!)
```

### Architectural Solution

#### Strategy: Schema Dependency Injection via AST Analysis

**Core Principle**: When a statement references a cross-schema object, inject the schema creation as a dependency.

#### Phase 1: AST-Based Schema Reference Detection

**Location**: `internal/parser/parser.go`

Add new method to extract schema references from AST:

```go
// ExtractSchemaReferences analyzes statement AST for cross-schema references
// Returns map of schema_name -> referenced_object
func (p *Parser) ExtractSchemaReferences(stmt *types.Statement) map[string][]string {
    if stmt.ParseTree == nil {
        return nil
    }

    parseResult, ok := stmt.ParseTree.(*pg_query.ParseResult)
    if !ok {
        return nil
    }

    schemaRefs := make(map[string][]string)

    for _, rawStmt := range parseResult.Stmts {
        // Extract schema references from different statement types
        switch node := rawStmt.Stmt.(type) {
        case *pg_query.CreatePolicyStmt:
            // Extract schema from table reference
            if node.Table != nil {
                schema, table := p.extractSchemaAndTable(node.Table)
                if schema != "" && schema != "public" {
                    schemaRefs[schema] = append(schemaRefs[schema], table)
                }
            }

        case *pg_query.CreateForeignTableStmt:
            // Foreign tables can reference schemas
            if node.Base != nil && node.Base.Relation != nil {
                schema := node.Base.Relation.Schemaname
                if schema != "" && schema != "public" {
                    schemaRefs[schema] = append(schemaRefs[schema], node.Base.Relation.Relname)
                }
            }

        // Add more cases for other cross-schema references
        }
    }

    return schemaRefs
}
```

#### Phase 2: Schema Lifecycle Tracking

**Location**: `internal/tracking/unified_tracker.go`

Extend tracker to track schemas as first-class objects:

```go
// ProcessSchemaCreation tracks schema creation events
func (t *UnifiedTracker) ProcessSchemaCreation(schemaName string, migration string, sequence int) {
    key := fmt.Sprintf("%s.SCHEMA", schemaName)

    lifecycle := t.getOrCreateLifecycle(key, schemaName, "", types.TypeSchema)
    lifecycle.Category = types.CategoryFoundation

    event := LifecycleEvent{
        Migration: migration,
        Sequence:  sequence,
        Operation: types.OpCreate,
        Statement: types.Statement{
            ObjectType: types.TypeSchema,
            Schema:     schemaName,
            Name:       schemaName,
        },
    }

    lifecycle.History = append(lifecycle.History, event)
}

// EnsureSchemaExists checks if schema exists and injects creation if needed
func (t *UnifiedTracker) EnsureSchemaExists(schemaName string, referencingStmt *types.Statement) {
    // Skip public schema (always exists)
    if schemaName == "" || schemaName == "public" {
        return
    }

    // Check if schema was created in migrations
    schemaKey := fmt.Sprintf("%s.SCHEMA", schemaName)
    if _, exists := t.objects[schemaKey]; exists {
        return // Schema exists
    }

    // Schema doesn't exist - inject implicit creation
    t.logger.Info("Injecting implicit schema creation for: %s (referenced by %s)",
        schemaName, referencingStmt.Name)

    // Create lifecycle for implicit schema
    lifecycle := t.getOrCreateLifecycle(schemaKey, schemaName, "", types.TypeSchema)
    lifecycle.Category = types.CategoryFoundation

    // Mark as implicit (injected by engine)
    lifecycle.Metadata = ObjectMetadata{
        IsImplicit: true,
        Reason:     fmt.Sprintf("Referenced by %s", referencingStmt.Name),
    }

    // Create event for schema creation
    event := LifecycleEvent{
        Migration: referencingStmt.Migration, // Same migration as referencer
        Sequence:  -1, // Before all other statements
        Operation: types.OpCreate,
        Statement: types.Statement{
            ObjectType: types.TypeSchema,
            Schema:     schemaName,
            Name:       schemaName,
            SQL:        fmt.Sprintf("CREATE SCHEMA IF NOT EXISTS %s;", schemaName),
            Category:   types.CategoryFoundation,
        },
    }

    lifecycle.History = append(lifecycle.History, event)
}
```

#### Phase 4: Builder Schema Injection

**Location**: `internal/builder/sql.go`

Modify builder to emit implicit schema creations:

```go
// BuildCategory builds SQL for a specific category, including implicit schemas
func (b *SQLBuilder) BuildCategory(category types.Category, objects []*tracking.ObjectLifecycle) (string, error) {
    var sqlParts []string

    // PHASE 1: Check if any objects in this category need implicit schemas
    implicitSchemas := make(map[string]bool)

    for _, obj := range objects {
        // Check if object has implicit schema dependency
        if obj.Metadata.IsImplicit && obj.Type == types.TypeSchema {
            implicitSchemas[obj.Schema] = true
        }

        // Check dependencies for schema requirements
        for _, dep := range obj.Dependencies {
            if dep.Type == types.DependencyTypeSchema && dep.IsImplicit {
                implicitSchemas[dep.Schema] = true
            }
        }
    }

    // PHASE 2: Emit implicit schema creations FIRST
    for schemaName := range implicitSchemas {
        schemaSQL := fmt.Sprintf("CREATE SCHEMA IF NOT EXISTS %s;\n", schemaName)
        sqlParts = append(sqlParts, schemaSQL)
        b.logger.Info("Emitted implicit schema creation: %s", schemaName)
    }

    // PHASE 3: Emit regular objects
    for _, obj := range objects {
        // Skip implicit schemas (already emitted)
        if obj.Metadata.IsImplicit && obj.Type == types.TypeSchema {
            continue
        }

        sql := b.buildObject(obj)
        sqlParts = append(sqlParts, sql)
    }

    return strings.Join(sqlParts, "\n"), nil
}
```

## BUG #2: Function Schema Differences After Squashing

### Severity & Impact
- **Severity**: HIGH
- **Priority**: P0
- **Impact**: Functions differ from originals, breaks equivalence guarantee
- **Frequency**: Common (affects all Clerk projects and functions with modifiers)

### Root Cause Analysis

#### The Problem
After squashing, 6 Clerk auth functions show schema differences:
- `current_clerk_org_role`
- `current_clerk_org_id`
- `get_planning_analytics`
- `current_clerk_user_id`
- `set_session_user`
- `validate_jwt_version`

The functions are **functionally equivalent** but not byte-identical due to:
1. STABLE volatility markers added when they shouldn't be
2. AST-to-SQL conversion producing different formatting
3. Function normalizer modifying signatures

#### Architectural Analysis

**Where the bug originates:**

1. **Function Normalizer** (`internal/postprocessing/ast/function_normalizer.go:180-272`):
   - `inferMissingLanguage()` adds or fixes LANGUAGE clauses
   - `inferLanguageFromFunction()` defaults to STABLE for all non-plpgsql functions
   - **BUG**: Lines 200-217 show it's adding STABLE to simple SQL functions that shouldn't have it

2. **Auth Compatibility Layer** (`internal/plugins/auth/compatibility.go:81-99`):
   - Mock functions in compatibility layer have `STABLE` markers:
   ```go
   CREATE OR REPLACE FUNCTION auth.jwt() RETURNS jsonb LANGUAGE plpgsql SECURITY DEFINER STABLE
   ```
   - These are TEST MOCKS, not production function definitions
   - **BUG**: The volatility markers from mocks are influencing production function normalization

3. **Deparser** (`internal/squasher/deparser.go:98-148`):
   - `deparseWithVolatilityPreservation()` tries to preserve volatility
   - Extracts volatility from **original SQL** and re-injects after deparsing
   - **BUG**: If original SQL doesn't have volatility marker, but normalizer adds one, there's a mismatch

4. **Function Normalizer Regex** (`function_normalizer.go:456-640`):
   - `ensureLanguageClausesPresent()` uses regex to insert LANGUAGE clauses
   - Handles RETURNS TABLE edge cases
   - **BUG**: Regex assumes certain SQL structure, but deparsed SQL may differ

**Evidence from logs** (e2e-nami-standard.log:86):
```
[ERROR-RECOVERY-DEBUG] current_clerk_org_id finalState.SQL length=149
SQL preview: CREATE OR REPLACE FUNCTION current_clerk_org_id()
RETURNS TEXT AS $$
  SELECT (auth.jwt()->'o'->>'id')::TEXT;
$$ LANGUAGE SQL STABLE SECURITY DEFINER
```

The function has **STABLE** added, but the original might not have had it.

### Architectural Solution

#### Strategy: Preserve Original Function Signatures with AST Validation

**Core Principle**: Functions should ONLY be modified if there's a consolidation (multiple versions). For single-version functions, preserve original SQL exactly.

#### Phase 1: Function Signature Preservation

**Location**: `internal/postprocessing/ast/function_normalizer.go`

Modify normalizer to be **conservative by default**:

```go
// NormalizeAll applies function normalizations ONLY when necessary
// NEW BEHAVIOR: Skip normalization for functions that appear only once in lifecycle
func (fn *FunctionNormalizer) NormalizeAll(sql string, lifecycle *tracking.ObjectLifecycle) (string, error) {
    // CRITICAL: If function has only ONE history event (single version), PRESERVE original SQL
    if lifecycle != nil && len(lifecycle.History) == 1 {
        fn.logger.Info("Function %s has single version - preserving original SQL exactly", lifecycle.Name)
        return sql, nil
    }

    // CRITICAL: If function was NOT modified by consolidation, preserve original
    if lifecycle != nil && !lifecycle.wasConsolidated() {
        fn.logger.Info("Function %s was not consolidated - preserving original SQL", lifecycle.Name)
        return sql, nil
    }

    // Parse SQL to AST
    parseResult, err := pg_query.Parse(sql)
    if err != nil {
        fn.logger.Info("Failed to parse SQL for AST normalization: %v", err)
        return sql, err // Return original on parse failure
    }

    // ... rest of normalization logic (only for multi-version functions)
}
```

#### Phase 3: AST-Based Volatility Detection

**Location**: `internal/postprocessing/ast/function_normalizer.go`

Replace heuristic volatility inference with AST-based detection:

```go
// inferLanguageFromFunction infers language AND volatility from AST analysis
func (fn *FunctionNormalizer) inferLanguageFromFunction(funcStmt *pg_query.CreateFunctionStmt) (language string, volatility string) {
    // Check if function returns TRIGGER - must be plpgsql
    if funcStmt.ReturnType != nil {
        returnType := fn.getTypeNameFromTypeName(funcStmt.ReturnType)
        if strings.ToLower(returnType) == "trigger" {
            return "plpgsql", "" // Triggers don't need volatility
        }
    }

    // Extract function body
    bodyStr := fn.extractFunctionBody(funcStmt)

    // Analyze body for plpgsql constructs
    if bodyStr != "" {
        bodyLower := strings.ToLower(bodyStr)

        // Check for plpgsql-specific constructs
        plpgsqlKeywords := []string{
            "begin", "declare", "perform ", "raise ",
            "return next", "return query", "if then", "loop",
        }

        for _, keyword := range plpgsqlKeywords {
            if strings.Contains(bodyLower, keyword) {
                return "plpgsql", "" // plpgsql functions - let PostgreSQL infer volatility
            }
        }

        // Check for SQL functions that modify data (VOLATILE)
        if strings.Contains(bodyLower, "insert ") ||
           strings.Contains(bodyLower, "update ") ||
           strings.Contains(bodyLower, "delete ") {
            return "sql", "" // Let PostgreSQL infer VOLATILE
        }

        // Simple SELECT-only SQL function - could be STABLE or IMMUTABLE
        // DO NOT assume STABLE - let PostgreSQL default (VOLATILE) unless explicitly set
        return "sql", ""
    }

    return "sql", "" // Default to SQL with no volatility assumption
}
```

**Key Change**: Remove automatic STABLE assignment. Let PostgreSQL's default behavior apply.

## BUG #3: Index on Non-Existent Column

### Severity & Impact
- **Severity**: MEDIUM
- **Priority**: P1
- **Impact**: Migration fails when applied, orphaned index definitions
- **Frequency**: Uncommon (only in complex schema evolution scenarios)

### Root Cause Analysis

#### The Problem
The engine creates an index on a column that was dropped:

```sql
-- Migration 1: Create column and index
CREATE TABLE matches (
    id UUID PRIMARY KEY,
    compatibility_score INTEGER
);
CREATE INDEX idx_matches_compatibility ON matches (compatibility_score);

-- Migration 2: Drop column
ALTER TABLE matches DROP COLUMN compatibility_score;

-- Squashed output (INCORRECT):
CREATE TABLE matches (
    id UUID PRIMARY KEY
    -- compatibility_score is MISSING (correctly dropped)
);
CREATE INDEX IF NOT EXISTS idx_matches_compatibility ON matches (compatibility_score);
-- ERROR: column "compatibility_score" does not exist
```

#### Architectural Analysis

**Where the bug originates:**

1. **Column Lifecycle Tracking** (`internal/tracking/unified_tracker.go`):
   - Tracker tracks table-level lifecycle (CREATE → ALTER → DROP)
   - **BUG**: Does NOT track column-level lifecycle within tables
   - When `ALTER TABLE DROP COLUMN` occurs, no column-level event is recorded
   - Index definitions reference columns, but this dependency is not tracked

2. **Index-Column Dependencies** (`internal/squasher/unified_dependency_resolver.go`):
   - Resolver tracks index → table dependencies
   - **BUG**: Does NOT track index → column dependencies
   - No validation that referenced columns still exist

3. **DROP/CREATE Consolidation** (`internal/tracking/consolidation/drop_create_rule.go`):
   - Merges multiple CREATE statements (handles DDL cycles)
   - Extracts column evolutions (renames: `name` → `market_name`)
   - **BUG**: Does NOT handle column DROPS
   - No cleanup of dependent indexes when column is dropped

4. **Column Evolution Tracking** (`drop_create_rule.go:117-122`):
   - `extractColumnEvolutionsFromMultipleCreates()` tracks renames
   - **BUG**: Only handles RENAME, not DROP
   - Indexes on dropped columns are not marked for removal

**The lifecycle that causes the bug:**

```
Table: matches
  Event 1: CREATE TABLE matches (id UUID, compatibility_score INTEGER)
  Event 2: ALTER TABLE matches DROP COLUMN compatibility_score

Index: idx_matches_compatibility
  Event 1: CREATE INDEX idx_matches_compatibility ON matches (compatibility_score)

CONSOLIDATION:
  Table: CREATE TABLE matches (id UUID) -- compatibility_score correctly removed
  Index: CREATE INDEX idx_matches_compatibility ON matches (compatibility_score) -- ORPHANED!
```

### Architectural Solution

#### Strategy: Column-Level Lifecycle Tracking with Index Dependency Cascade

**Core Principle**: Track column lifecycle separately. When a column is dropped, cascade delete to all dependent objects (indexes, constraints).

#### Phase 1: Column Lifecycle Tracking

**Location**: `internal/tracking/unified_tracker.go`

Add column-level tracking:

```go
// ColumnLifecycle tracks individual column evolution
type ColumnLifecycle struct {
    TableName    string
    ColumnName   string
    DataType     string
    IsDropped    bool
    History      []ColumnEvent
    DependentObjects []string // Indexes, constraints that depend on this column
}

// ColumnEvent represents a column-level operation
type ColumnEvent struct {
    Migration string
    Sequence  int
    Operation types.Operation // CREATE, ALTER, DROP, RENAME
    OldName   string          // For RENAME operations
    NewName   string          // For RENAME operations
    SQL       string
}

// UnifiedTracker extended with column tracking
type UnifiedTracker struct {
    // ... existing fields ...

    // NEW: Column-level tracking
    columnLifecycles map[string]*ColumnLifecycle // key: "schema.table.column"
    columnRenames    map[string]string           // old_name -> new_name
}

// TrackColumnOperation tracks column-level changes from ALTER TABLE
func (t *UnifiedTracker) TrackColumnOperation(tableName string, columnOp *ColumnOperation) {
    key := fmt.Sprintf("%s.%s", tableName, columnOp.ColumnName)

    lifecycle := t.columnLifecycles[key]
    if lifecycle == nil {
        lifecycle = &ColumnLifecycle{
            TableName:  tableName,
            ColumnName: columnOp.ColumnName,
        }
        t.columnLifecycles[key] = lifecycle
    }

    event := ColumnEvent{
        Migration: columnOp.Migration,
        Sequence:  columnOp.Sequence,
        Operation: columnOp.Operation,
        SQL:       columnOp.SQL,
    }

    switch columnOp.Operation {
    case types.OpDrop:
        lifecycle.IsDropped = true
        t.logger.Info("Column %s.%s marked as DROPPED", tableName, columnOp.ColumnName)

    case types.OpRename:
        event.OldName = columnOp.OldName
        event.NewName = columnOp.NewName
        t.columnRenames[columnOp.OldName] = columnOp.NewName
        t.logger.Info("Column %s.%s RENAMED to %s", tableName, columnOp.OldName, columnOp.NewName)
    }

    lifecycle.History = append(lifecycle.History, event)
}
```

#### Phase 2: AST-Based Column Operation Extraction

**Location**: `internal/parser/parser.go`

Extract column operations from ALTER TABLE statements:

```go
// ExtractColumnOperations extracts column-level operations from ALTER TABLE AST
func (p *Parser) ExtractColumnOperations(stmt *types.Statement) []*ColumnOperation {
    if stmt.ObjectType != types.TypeTable && stmt.Operation != types.OpAlter {
        return nil
    }

    parseResult, ok := stmt.ParseTree.(*pg_query.ParseResult)
    if !ok {
        return nil
    }

    var operations []*ColumnOperation

    for _, rawStmt := range parseResult.Stmts {
        alterStmt := rawStmt.Stmt.GetAlterTableStmt()
        if alterStmt == nil {
            continue
        }

        tableName := alterStmt.Relation.Relname

        // Process each ALTER TABLE command
        for _, cmd := range alterStmt.Cmds {
            alterCmd := cmd.GetAlterTableCmd()
            if alterCmd == nil {
                continue
            }

            switch alterCmd.Subtype {
            case pg_query.AlterTableType_AT_DropColumn:
                // Extract column name from AST
                columnName := p.extractColumnNameFromCmd(alterCmd)
                operations = append(operations, &ColumnOperation{
                    TableName:  tableName,
                    ColumnName: columnName,
                    Operation:  types.OpDrop,
                    SQL:        stmt.SQL,
                })

            case pg_query.AlterTableType_AT_ColumnRename:
                oldName := p.extractOldColumnName(alterCmd)
                newName := p.extractNewColumnName(alterCmd)
                operations = append(operations, &ColumnOperation{
                    TableName:  tableName,
                    OldName:    oldName,
                    NewName:    newName,
                    Operation:  types.OpRename,
                    SQL:        stmt.SQL,
                })

            case pg_query.AlterTableType_AT_AddColumn:
                columnName := p.extractColumnNameFromCmd(alterCmd)
                dataType := p.extractColumnType(alterCmd)
                operations = append(operations, &ColumnOperation{
                    TableName:  tableName,
```

```go
// ExtractIndexColumns extracts column names from index definition AST
func (p *Parser) ExtractIndexColumns(stmt *types.Statement) []string {
    if stmt.ObjectType != types.TypeIndex {
        return nil
    }

    parseResult, ok := stmt.ParseTree.(*pg_query.ParseResult)
    if !ok {
        return nil
    }

    var columns []string

    for _, rawStmt := range parseResult.Stmts {
        indexStmt := rawStmt.Stmt.GetIndexStmt()
        if indexStmt == nil {
            continue
        }

        // Extract columns from index parameters
        for _, param := range indexStmt.IndexParams {
            indexElem := param.GetIndexElem()
            if indexElem != nil && indexElem.Name != "" {
                columns = append(columns, indexElem.Name)
            }
        }
    }

    return columns
}
```

#### Phase 4: Orphaned Index Detection and Removal

**Location**: `internal/tracking/consolidation/advanced_column_lifecycle_rule.go`

Create new rule to detect and remove orphaned indexes:

```go
// OrphanedIndexCleanupRule removes indexes on dropped columns
type OrphanedIndexCleanupRule struct{}

func (r *OrphanedIndexCleanupRule) CanApply(lifecycle *tracking.ObjectLifecycle) bool {
    // Apply to indexes only
    return lifecycle.Type == types.TypeIndex
}

func (r *OrphanedIndexCleanupRule) Apply(lifecycle *tracking.ObjectLifecycle, engine ConsolidationEngine) (*tracking.ConsolidationResult, error) {
    // Get the table this index belongs to
    tableName := lifecycle.Schema + "." + extractTableFromIndex(lifecycle)

    // Get index columns from AST
    indexColumns := engine.ExtractIndexColumns(lifecycle)

    // Check if any referenced column was dropped
    tracker := engine.GetTracker()
    for _, columnName := range indexColumns {
        columnKey := fmt.Sprintf("%s.%s", tableName, columnName)
        columnLifecycle := tracker.GetColumnLifecycle(columnKey)

        if columnLifecycle != nil && columnLifecycle.IsDropped {
            // Column was dropped - mark index as orphaned
            engine.logger.Info("Index %s references dropped column %s - marking for removal",
                lifecycle.Name, columnName)

            return &tracking.ConsolidationResult{
                OriginalStatements: extractStatements(lifecycle),
                ConsolidatedSQL:    "", // Empty - index is removed
                Optimizations:      []string{
                    fmt.Sprintf("Removed orphaned index on dropped column: %s", columnName),
                },
                RiskLevel:       tracking.RiskLevelLow,
                WasRemoved:      true,
                RemovalReason:   fmt.Sprintf("Column %s was dropped", columnName),
            }, nil
        }

        // Check if column was renamed
        if newName, wasRenamed := tracker.GetColumnRename(columnName); wasRenamed {
            // Column was renamed - update index definition
            engine.logger.Info("Index %s references renamed column %s -> %s",
                lifecycle.Name, columnName, newName)

            // Rewrite index SQL with new column name
            updatedSQL := rewriteIndexColumnsInAST(lifecycle, map[string]string{
                columnName: newName,
            })

            return &tracking.ConsolidationResult{
                OriginalStatements: extractStatements(lifecycle),
                ConsolidatedSQL:    updatedSQL,
                Optimizations:      []string{
                    fmt.Sprintf("Updated index to use renamed column: %s -> %s", columnName, newName),
                },
                RiskLevel: tracking.RiskLevelLow,
            }, nil
        }
    }

    // No orphaned columns - preserve index
    return nil, nil
}

// rewriteIndexColumnsInAST rewrites index definition with updated column names (AST-based)
func rewriteIndexColumnsInAST(lifecycle *tracking.ObjectLifecycle, renames map[string]string) string {
    // Get parse tree
    stmt := lifecycle.History[len(lifecycle.History)-1].Statement
    parseResult, ok := stmt.ParseTree.(*pg_query.ParseResult)
    if !ok {
        return stmt.SQL // Fallback to original
    }

    // Modify AST to update column names
    for _, rawStmt := range parseResult.Stmts {
        indexStmt := rawStmt.Stmt.GetIndexStmt()
        if indexStmt == nil {
            continue
        }

        // Update column names in index parameters
        for _, param := range indexStmt.IndexParams {
            indexElem := param.GetIndexElem()
            if indexElem != nil && indexElem.Name != "" {
                if newName, exists := renames[indexElem.Name]; exists {
                    indexElem.Name = newName
                }
            }
        }
    }

    // Deparse back to SQL
    deparsed, err := pg_query.Deparse(parseResult)
    if err != nil {
        return stmt.SQL // Fallback
    }

    return deparsed
}
```

## Common Patterns Across Bugs

### Pattern 1: Missing Dependency Tracking
**Bugs Affected**: #1 (schemas), #3 (columns)

**Root Cause**: Tracker only tracks object-level dependencies, not sub-object or schema-level dependencies.

**Solution**: Hierarchical dependency tracking:
- Schema → Tables/Functions/Policies
- Table → Columns
- Index → Columns
- Policy → Schema (cross-schema)

### Pattern 2: AST vs String Processing
**Bugs Affected**: #2 (function normalization), #3 (column extraction)

**Root Cause**: Mixing AST-based and regex-based processing leads to inconsistencies.

**Solution**: Enforce AST-first principle:
- All structural modifications use AST
- Regex only for final formatting
- Parser extracts all dependencies from AST

### Pattern 3: Compatibility Layer Leakage
**Bugs Affected**: #2 (volatility markers from mocks)

**Root Cause**: Test/validation code influencing production behavior.

**Solution**: Strict separation:
- Compatibility layer is for validation ONLY
- Production consolidation ignores compatibility hints
- Mock functions should match PostgreSQL defaults, not add extras

## Conclusion

All three bugs share a common theme: **incomplete dependency tracking and state management**. The solutions follow pgsquash's architectural principles:

1. **AST-First**: All structural analysis uses pg_query AST, not regex
2. **Tracker as Source of Truth**: Extend tracker to capture schema and column-level state
3. **Dependency-Driven**: Proper dependency graphs prevent ordering issues
4. **Conservative by Default**: Preserve original SQL unless consolidation is required

By implementing these architectural solutions, pgsquash will have:
- **Robust schema management** (cross-schema dependencies tracked)
- **Exact function preservation** (single-version functions unchanged)
- **Column-aware consolidation** (orphaned objects cleaned up)

These improvements will make the engine production-ready for complex, real-world migration scenarios.
