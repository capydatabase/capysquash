## Bug #5: Missing Role Creation (CRITICAL)

### Problem
Squashed SQL referenced roles (\`authenticated\`, \`anon\`, \`service_role\`) in RLS policies but never created them, causing immediate deployment failures.

### Solution
Enhanced role detection in **engine.go:1335-1386** to check for "TO authenticated/anon/service_role" patterns and create roles BEFORE all SQL generation.

✅ **Result**: Squashed SQL now deploys successfully without role errors.

## Bug #2: Poor SQL Formatting (HIGH)

### Problem
All SQL output was concatenated on single lines without proper formatting, making code review impossible.

### Solution
Added formatting at three levels:
1. **deparser.go**: Format each deparsed statement
2. **statement_formatter.go** (NEW): AST-aware formatter with regex fallback
3. **postprocessor.go**: Phase 5 formatting cleanup

✅ **Result**: SQL output is now readable and suitable for code review.

## Bug #1: Validation Logic Contradictions (HIGH)

### Problem
Validation reported the same objects in multiple contradictory categories (only in original, only in squashed, AND differs).

### Solution
Complete rewrite of \`compareObjects()\` in **schema_normalizer.go:531-597** to use name-based comparison with single-pass logic.

✅ **Result**: Each object appears in exactly ONE category. Validation is now trustworthy.
