# pgsquash Integration Scripts

This directory contains integration scripts to help you use pgsquash with popular migration tools and platforms.

## 📋 Available Scripts

### 1. Prisma Baseline (`prisma-baseline.sh`)

Applies squashed migrations and marks old migrations as applied in Prisma’s migration tracking system.

**Prerequisites:**

- `jq` installed (`brew install jq` or `apt-get install jq`)
- `DATABASE_URL` environment variable set
- `.squashmap.json` file (generated by pgsquash)

**Usage:**

```bash

# Set your database URL

export DATABASE_URL='postgresql://user:password@localhost:5432/dbname'

# Run pgsquash first

pgsquash squash migrations/ -o squashed/

# Apply baseline and mark migrations

./scripts/prisma-baseline.sh
```

**What it does:**

1. Reads `.squashmap.json` to identify original migrations
2. Applies the squashed baseline schema to your database
3. Applies data operations (if any)
4. Marks all original migrations as applied using `prisma migrate resolve`

**After running:**

- Commit the squashed migrations
- Team members should pull and run: `npx prisma migrate deploy`
- Delete old migration files from `prisma/migrations/`

---

### 2. Drizzle Reset (`drizzle-reset.sh`)

Resets your database and migration tracking for Drizzle ORM after squashing.

**Prerequisites:**

- `jq` installed
- `DATABASE_URL` environment variable set
- `.squashmap.json` file (generated by pgsquash)
- Drizzle migrations directory (`drizzle/` or `migrations/`)

**Usage:**

```bash

# Set your database URL

export DATABASE_URL='postgresql://user:password@localhost:5432/dbname'

# Run pgsquash first

pgsquash squash migrations/ -o squashed/

# Reset database and apply squashed migrations

./scripts/drizzle-reset.sh
```

**What it does:**

1. Creates a backup of your migrations directory
2. Drops the `__drizzle_migrations` tracking table
3. Applies the squashed baseline schema
4. Applies data operations (if any)
5. Reorganizes migration files
6. Regenerates Drizzle metadata

**⚠️ Warning:** This script is DESTRUCTIVE. It will:

- Drop all migration tracking
- Replace migration files
- Require team coordination

**After running:**

- Test your application thoroughly
- Commit the new migration structure
- Have team members drop their local databases and re-sync

## 🚀 GitHub Actions Workflow

### Neon Validation (`../.github/workflows/pgsquash-validate.yml`)

Automatically validates squashed migrations on pull requests using Neon’s ephemeral branches.

**Setup:**

1. Add secrets to your GitHub repository:

- `NEON_PROJECT_ID`: Your Neon project ID
- `NEON_API_KEY`: Your Neon API key

2. The workflow will:

- Create an ephemeral Neon branch for each PR
- Run pgsquash validation
- Comment on the PR with results
- Clean up the branch automatically

**Triggers:**

- Pull requests that modify `migrations/`, `squashed/`, or `.squashmap.json`
- Manual workflow dispatch

## 📝 Best Practices

### General Guidelines

1. **Always backup before squashing:**
   ```bash
   # Create a backup

   pg_dump $DATABASE_URL > backup_$(date +%Y%m%d).sql
   ```

2. **Test in development first:**

- Never squash directly in production
- Test the squashed migrations in a dev/staging environment

3. **Coordinate with your team:**

- Announce squashing plans in advance
- Ensure no one has pending migrations
- Use `--branch-check` to enforce protected branch requirement

4. **Use version control:**

- Commit squashed migrations separately
- Tag the commit for easy rollback
- Keep `.squashmap.json` for traceability

### Prisma-Specific

- Run `npx prisma migrate status` before and after to verify
- Use `prisma migrate resolve --rolled-back` if you need to undo
- Keep the `_prisma_migrations` table intact

### Drizzle-Specific

- The reset script is destructive - use with caution
- Always test with a database dump first
- Coordinate database resets with your team

### Neon-Specific

- Ephemeral branches are perfect for validation
- Use the GitHub Action for automatic PR validation
- Consider using Neon branches for each developer

## 🔧 Troubleshooting

### "jq: command not found"

Install jq:

- macOS: `brew install jq`
- Ubuntu/Debian: `sudo apt-get install jq`
- ubuntu: `apk add jq`

### "DATABASE_URL not set"

Export your database connection string:

```bash
export DATABASE_URL='postgresql://user:password@host:port/database'
```

### Prisma: "Migration not found"

The migration might already be marked as applied. Check with:

```bash
npx prisma migrate status
```

### Drizzle: "Permission denied"

Make the script executable:

```bash
chmod +x scripts/drizzle-reset.sh
```
